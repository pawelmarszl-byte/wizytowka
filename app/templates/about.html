How it works

A portfolio project. Here's the story behind it and what's under the hood.

The problem

In a finance team, someone has to check every day that the company's books match its bank account. Done by hand it means downloading PDFs, retyping lines into the accounting system and hunting for differences in spreadsheets. It's slow, and mistakes such as a payment booked twice or two swapped digits slip through.

I built an internal tool that automates this for my own work. Ledgerly is a public rewrite of that idea, made from scratch with invented data so anyone can try it. More about me →

What to look for

  • Real PDF reading. Statements are generated as genuine PDFs and parsed back from text. The "doesn't add up" check is computed, not scripted.
  • Safety checks before automation. A statement that doesn't balance can't be posted.
  • Explainable results. Each difference is classified (duplicate, typo, timing, phantom entry) and described in plain language.
  • Audit-friendly fixes. Corrections are new entries; nothing is silently deleted.
  • Failure handling. Click a dot in the status bar to cut a connection and see how the app behaves.

Under the hood

  • Backend Python 3.12 · FastAPI · Jinja2
  • Frontend HTMX - server-rendered HTML fragments, no JS framework, no build step
  • Charts SVG drawn on the server
  • PDF fpdf2 to generate, pypdf to read
  • Data deterministic generator (seed 42), isolated in-memory session per visitor
  • Quality unit + HTTP tests, GitHub Actions CI, a test that blocks real company names from the repo
  • Hosting Render free tier (the first visit after a quiet spell takes ~30 s to wake up)

About the data

Harbor Bank, Ledgerly Demo Ltd. and every customer, supplier and amount are fictional. Your session is private to your browser and disappears after a few hours or when you press Reset demo.
